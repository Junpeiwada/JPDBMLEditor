# 計画 - 列幅調整（Excel 風リサイズ）

テーブルノードの列幅調整を **Excel の列幅調整と同じ挙動**に作り直す。
現状は「箱全体リサイズ」と「列境界リサイズ」の 2 系統が併存し、名前列だけ `1fr`（余りを吸う）
特殊扱いのため両者が干渉し、掴んだときにどの列がどう動くかが読みにくい。描画も乱れやすい。
これを **列単位のリサイズに一本化**して整理する。

関連: [UI設計.md](UI設計.md) / 実装ファイル [TableNode.tsx](../src/view/TableNode.tsx),
[ErCanvas.tsx](../src/view/ErCanvas.tsx), [nodeSize.ts](../src/layout/nodeSize.ts),
[sidecar.ts](../src/meta/sidecar.ts)

---

## 1. 決定事項（2026-07-14 ユーザー確認済み）

| 論点 | 決定 |
|---|---|
| 操作系統 | **列単位に一本化**。箱全体の右端リサイズハンドルは廃止。列境界ドラッグ + ダブルクリックのみ。 |
| 名前列の扱い | 名前列も**固定 px** 化（`1fr` をやめる）。型・note と同じ「境界ドラッグで伸縮する 1 列」として扱う。 |
| オートフィット基準 | **実測（DOM 計測）**。実際にレンダリングされたセル内容の最大幅を測ってフィットする。 |
| リサイズ対象列 | 名前列・型列・note 列の**すべて**。note が無いテーブルでも型列を右端で伸縮できる。 |
| 箱全体の幅 | 列幅の合計から**自動追従**（ユーザーは箱を直接リサイズしない）。 |

---

## 2. 理想の仕様（Excel と揃える）

### 2.1 列境界ドラッグ（幅の手動変更）

- 各列の**右端（境界）**にリサイズハンドルを置く。ハンドルはホバー時のみ薄く表示（常時表示だと
  大量テーブルで描画が重くなる既存方針を踏襲）。カーソルは `col-resize`。
- 境界を掴んでドラッグすると、**境界の左側の列**だけが伸縮する。**他の列の幅は一切変わらない**。
  右側の列は「位置がずれるだけ」。← Excel と同じ。
- ドラッグ中はローカル state でプレビュー（React Flow の nodes は触らない＝軽い）。離した瞬間に
  1 回だけ確定通知する（既存の `resizingCols` 方式を踏襲）。
- 列幅の**下限**を設ける（`COLUMN_MIN_WIDTH`。現状 24px）。0 幅や負値は禁止。
- **どの列の右端か**の対応（note 有無で境界が変わる）:

  | 列レイアウト | 境界と対象列 |
  |---|---|
  | note あり | `[icon] [名前]│[型]│[note]│` → 名前右端=名前列 / 型右端=型列 / note右端=note列 |
  | note なし | `[icon] [名前]│[型]│` → 名前右端=名前列 / 型右端=型列 |

  ※ 現状は「名前↔型」「型↔note」の内側境界しか無く、**一番右の列（note、または note 無しなら型）の
  右端**を掴めない。ここを追加して全列を伸縮可能にする（決定事項＝全列対象）。

### 2.2 ダブルクリックでオートフィット

- 列境界を**ダブルクリック**すると、その列を「その列で一番長い内容にぴったり合う幅」に自動調整する。
  ← Excel の「境界ダブルクリックで最適幅」と同じ。
- フィット幅は**実測**する。対象テーブルの対象列セル（`data-cell` で識別）の実 DOM 幅（`scrollWidth`）の
  最大値 + 左右パディングを列幅とする。文字数概算のズレ（日本語・記号）を無くす。
- 実測後の幅を override として保存する（＝「内容に合わせた明示的な幅」を持つ）。
  - 補足: 現状のオートフィットは「override を削除して文字数概算に戻す」実装。実測に変えると
    概算に戻すのではなく**測った値を明示 override として持つ**方針に変わる点に注意。

### 2.3 箱（ノード外形）の幅

- ユーザーは箱を直接リサイズしない。箱幅は**列幅の合計**（アイコン + 名前 + 型 + note + ギャップ +
  パディング）から自動算出し、列を広げれば箱も右へ広がる。
- 箱が広がったら、右隣で重なるテーブルを押し出す（既存 `resolveOverlapToRight` を踏襲）。
- ヘッダー（テーブル名 + note）が列幅合計より広い場合は、ヘッダー幅を下限にする（名前が切れない）。

### 2.4 永続化（.jpdbml.json）

- 手動で変えた列幅（名前/型/note の px）を `columnWidths` に保存（既存スキーマを流用）。
- 全列が自動概算と一致する状態に戻したら、その列の override を落とす（サイドカーを汚さない）。
- 箱幅 `tableWidths` は**列一本化に伴い原則不要**になる（箱は列合計から算出されるため）。
  → 既存の `tableWidths` 保存/読み込みの扱いは §4 で整理（後方互換は維持し、書き込みは止める）。

## 3. 現状の描画がうまくいっていない原因（推定）

列単位一本化の前に、なぜ今の描画が乱れるかを整理する。作り直しで下記が解消される想定。

1. **名前列が `1fr`**（[TableNode.tsx](../src/view/TableNode.tsx) `rowGridTemplate`）:
   `minmax(name px, 1fr)` のため、箱幅と列幅合計の差を名前列が吸う。箱幅は
   `estimateTableNodeSize` の**文字数概算**で決まるので、概算と実測がズレると名前列が
   意図せず伸び縮みし、列の左端が縦に揃わなく見える／余白やはみ出しが出る。
   → **名前列を固定 px 化**すれば、列テンプレートが全列固定になり縦の整列が安定する。
2. **2 系統のハンドル干渉**: 箱リサイズ（名前列が吸う）と列リサイズ（左列を伸縮）が両方あるため、
   同じ「名前列」を別経路で変える操作が競合する。→ **箱リサイズ廃止**で一本化。
3. **概算と実測のズレ**: `CHAR_WIDTH=7px` 固定の概算はフォント/日本語で誤差が出る。列幅ぴったりに
   詰めると内容が切れる、または余る。→ **オートフィットを実測**にし、初期概算はあくまで
   「measured 前の暫定」と割り切る。
4. **一番右の列の右端を掴めない**: note 列（or note 無しの型列）を広げる手段が無い。→ 右端境界を追加。

※ 「描画が乱れる」の具体的な再現手順（どのサンプル・どの操作でどう崩れるか）が分かれば、原因の
確証が上がる。実装着手前に 1 ケースでよいので再現を掴んでおく（§5 の Step 0）。

## 4. 実装方針（ファイル別）

### nodeSize.ts

- `computeColumnWidths`: 変更なし（名前列も px を返す既存仕様のまま。自動時はテーブル内最大文字幅）。
- `estimateTableNodeSize`: 名前列も含めた列幅合計を箱幅にする（既存ロジック流用）。`MAX_WIDTH`
  クランプの扱いは override 有無で分岐する現状を踏襲。
- 実測オートフィット用に、DOM から測った幅を受け取って override 化する導線は ErCanvas/TableNode 側。

### TableNode.tsx

- **箱リサイズハンドル（`table-resize-handle` と `handleResizeMouseDown`）を削除**。`onResizeWidth` も外す。
- `rowGridTemplate`: 名前列を `minmax(name,1fr)` → **固定 `${name}px`** に変更（全列固定）。
- 列境界ハンドルを **名前右端 / 型右端 / note右端**（note 無しなら型が最右）に対応させる。
  現状の「名前↔型」「型↔note」の内側 2 本 + **最右列の右端** を追加。
- ダブルクリック時は、対象列のセル DOM（`[data-cell="name|type|note"]`）を全行走査して
  `scrollWidth` の最大値を測り、`onAutoFitColumn(tableId, field, measuredWidth)` として通知する
  （＝実測値を渡す。現状は幅を渡さず「削除」だったのを、測った px を渡す形に変更）。

### ErCanvas.tsx

- `handleColumnResize`（箱リサイズ確定）と `onResizeWidth` 配線を削除。
- `handleColumnAutoFit`: 引数に実測幅を受け取り、`buildNextColumnWidths(table, field, measuredWidth)` で
  override をセットする（null 渡し＝概算に戻す、を廃止）。
- `handleColumnWidthResize`（列境界ドラッグ確定）は流用。field に `'note'` の最右対応を確認。
- `buildNextColumnWidths`: 「measuredWidth が自動概算と一致したら override を落とす」判定は残す
  （＝ぴったり自動幅なら保存しない）。

### sidecar.ts

- `columnWidths` スキーマは流用（name/type/note の px）。
- `tableWidths` は**読み込みは後方互換で残す**が、**新規書き込みは行わない**（箱は列合計から算出）。
  既存ファイルに `tableWidths` があっても列幅から再計算するため実害なし（要動作確認）。

## 5. 作業ステップ

- **Step 0**: 描画が乱れる現象を 1 ケース再現・記録（サンプル DBML + 操作手順）。§3 の原因確証。
- **Step 1**: 名前列を固定 px 化（`1fr` 廃止）。箱リサイズハンドルを削除。→ 縦整列が安定するか確認。
- **Step 2**: 最右列の右端リサイズハンドルを追加（note / note 無しなら型）。全列を境界ドラッグ可能に。
- **Step 3**: ダブルクリックのオートフィットを実測（`scrollWidth`）ベースに変更。
- **Step 4**: サイドカー整理（`tableWidths` 書き込み停止・後方互換読み込み維持）。
- **Step 5**: サンプル DBML（大規模 / 小規模）で回帰確認。日本語 note・大量カラムでの整列と
  オートフィットのフィット精度、押し出しの妥当性を目視確認。

各ステップ完了時点で単体で動く状態を保つ（実装計画の方針を踏襲）。

## 6. 受け入れ条件（Excel と同じと言える基準）

- [ ] 列境界を掴んでドラッグすると、掴んだ列だけが伸縮し、他列の幅は変わらない。
- [ ] 名前列・型列・note 列のすべてを境界ドラッグで伸縮できる（note 無しテーブルでも型列を伸縮可）。
- [ ] 列境界のダブルクリックで、その列が「一番長い内容」にぴったり合う（内容が切れない／無駄な余白が出ない）。
- [ ] 列を広げると箱が右へ広がり、右隣テーブルを押し出す。列を戻すと箱も戻る。
- [ ] 全行で列の左端が縦に揃う（ガタつかない）。
- [ ] 手動幅は `.jpdbml.json` に保存され、再読み込みで復元される。自動幅ぴったりに戻すと保存から消える。

## 7. 実装メモ(2026-07-14)

実装(§5 Step1〜4)にあたり、レビューで判明した以下4点を計画に対して補正した。

1. **オートフィットの実測方法を `scrollWidth` から `Range` ベースに変更**した理由:
   `scrollWidth` は `max(表示幅, 内容幅)` を返すため、列が内容より広い状態からのダブルクリックでは
   常に現状幅が下限になり「縮める」フィットができない(§6 受け入れ条件「無駄な余白が出ない」を
   満たせない)。代わりに対象列の `[data-cell]` 要素を全行 `querySelectorAll` し、各要素へ
   `document.createRange()` → `range.selectNodeContents(el)` → `getBoundingClientRect().width`
   でテキストの実描画幅を取り、最大値+バッファ(4px)を測定幅とした。ズーム(CSS transform)後の
   見かけ幅なので、列ドラッグと同じ `rootRef` の見かけ幅/論理幅比で割り戻している。
   `onAutoFitColumn` は `(tableId, field, measuredWidth)` を渡す形に変更し(null=削除呼び出しは廃止)、
   `buildNextColumnWidths` 側の一致判定は Math.round 同士の厳密一致ではなく **±2px の近似一致**で
   override を落とすようにした(Range実測は±1px程度ブレるため)。

2. **箱幅を列合計へ常時追従(縮む方向も)させた**: `applyColumnWidths` の
   `newNodeWidth = Math.max(currentWidth, neededWidth)` (据え置き)をやめ、
   `newNodeWidth = neededWidth` (estimateTableNodeSizeの結果そのまま)に変更。ユーザーが箱を
   直接リサイズする手段が無くなった以上、「列を戻すと箱も戻る」ためには常時追従が必須だった。
   これに伴い `tableWidths` のサイドカー書き込みは完全に停止し(常に空マップを書く)、
   `ErCanvas` の `savedWidths`/`onWidthsChange` props は削除した。`SidecarData.tableWidths` の
   スキーマ・`readSidecar` の読み込みは後方互換のため変更していない。

3. **列境界ハンドルの配置基準を right から left に変更**: 名前列を固定px化した結果、
   ヘッダー幅(テーブル名)が列合計より広いテーブルでは列が左詰めのまま右側に余白ができ、
   right基準オフセットでは境界位置がずれる。left基準(`ROW_PADDING_X + ICON_COL_WIDTH + ...`の
   積み上げ)に変更し、`transform: translateX(-50%)` で境界中心に重ねるようにした。
   あわせて型列右端ハンドルを常時描画(note有無に関わらず)に変更し、note列がある場合のみ
   note右端ハンドルを追加する形にした(全列を境界ドラッグ可能にする決定事項どおり)。

4. **箱幅の自動概算上限(MAX_WIDTH=560)クランプを廃止**: 全列固定pxグリッドは列幅合計を
   そのまま敷くため、箱だけをクランプすると列が箱(overflow:hidden)からはみ出し、右端の列と
   リサイズハンドルに届かなくなる(固定pxグリッドとの両立不可)。override 有無での分岐もなくし、
   常に `max(MIN_WIDTH, max(headerWidth, contentWidth) + 8)` を採用する。note 列は
   `NOTE_MAX_WIDTH=180` で引き続き列側に上限があるため、箱が際限なく横に伸びることはない。

その他、列ドラッグ中(`resizingCols`)は固定px化した行グリッドが箱からはみ出さないよう、
`TableNode` のルート `Box` の `width` を `estimateTableNodeSize` によるローカル先取り値
(`previewWidth`)で一時的に上書きするようにした(確定後は親の `node.style.width` に委ねる)。

## 追記(2026-07-14): 自動列幅を canvas measureText の実測ベースへ移行

上記「概算と実測のズレ(`CHAR_WIDTH=7px` 固定)」の根本対応。大文字英字を含むカラム名
(例: `HKDメンテナンス数` = 実描画128.5px に対し概算119px)で、表示の「…」省略と
インライン編集欄の見切れが実データで起きていたため、**初期自動幅も実測に移行**した
(オートフィットだけでなく)。経緯と実測値は [設計-行オーバレイ.md](設計-行オーバレイ.md) を参照。

- `computeColumnWidths` は文字数概算(`estimateTextWidth`)ではなく、canvas `measureText` で
  実フォント(名前=body2 14px / 型・note=caption 12px、letterSpacing 加算)を測る
  (`cellTextWidth`、結果はキャッシュ)。丸め対策の安全余白 +2px(`CELL_MEASURE_BUFFER`)。
- canvas が無い環境(Node の verify スクリプト等)は従来概算へフォールバックする。
- ヘッダー幅と LOD の表名フォントフィットは従来概算のまま(いずれも余白/安全係数を持つ用途)。
- 副次効果: オートフィット(Range実測)と自動幅がほぼ一致するようになり、±2px 近似一致での
  override 削除が自然に機能する。
