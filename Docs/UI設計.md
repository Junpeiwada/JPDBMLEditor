## 設計方針

- **上部バー + 左サイドパネル + 中央キャンバス**の 3 領域構成。情報量が増えても整理しやすい定番レイアウト。
- **キャンバスが主役**。左パネルは折りたたみ可能で、キャンバスを最大化できる。
- **状態は 3 モード**（全体 / 絞り込み / フォーカス）で、常にどのモードにいるか一目で分かるようにする。
- **編集は「フォーカス中テーブル」に対してのみ**行える（全体設計の方針に準拠）。誤操作防止のため編集 UI は明示的に開く。
- キーボードでも主要操作（検索フォーカス、モードリセット）ができる。

## 全体レイアウト

```
┌──────────────────────────────────────────────────────────────────────┐
│  JPDBMLEditor  [🔍 検索: テーブル名・カラム名 ] [×]  [↺][⟲][⟳] [💾保存]│  ← A. トップバー
├────────────────┬─────────────────────────────────────────────────────┤
│ B. 左パネル     │  C. ER 図キャンバス                          [全体▼] │
│ ┌────────────┐ │                                                     │
│ │ テーブル一覧 │ │      ┌──────────┐          ┌──────────┐          │
│ │ ─────────── │ │      │ users     │──────────│ orders    │          │
│ │ ▸ users     │ │      │──────────│  1     N  │──────────│          │
│ │ ▸ orders    │ │      │ 🔑 id     │          │ 🔑 id     │          │
│ │ ▸ products  │ │      │ name      │          │ user_id   │          │
│ │ ▸ ...       │ │      │ ...       │          │ ...       │          │
│ │            │ │      └──────────┘          └──────────┘          │
│ ├────────────┤ │                                                     │
│ │ フォーカス設定│ │                                                     │
│ │ 対象: users  │ │                                        ┌─────────┐ │
│ │ ホップ: [1]  │ │                                        │ + − ⊡ ⟳ │ │ ← ズーム等
│ │ ○───●───── │ │                                        └─────────┘ │
│ │ [全体に戻る] │ │                                                     │
│ └────────────┘ │                                                     │
├────────────────┴─────────────────────────────────────────────────────┤
│  ./sample.dbml *  12 テーブル / 18 リレーション                       │  ← ステータスバー（* = 未保存）
└──────────────────────────────────────────────────────────────────────┘
```

- **A. トップバー**: アプリ名 + 検索フィールド（常設）+ 検索クリアボタン + **手動リロード（↺）/ Undo（⟲）/ Redo（⟳）/ 保存（💾）ボタン**
  （2026-07-14 追加。詳細は [計画-保存UNDO計画.md](計画-保存UNDO計画.md)）。
- **B. 左サイドパネル**: 上段「テーブル一覧」、下段「フォーカス設定」。折りたたみ可能（`⟨` ボタン）。
- **C. ER 図キャンバス**: React Flow。右上にモード表示、右下にズーム操作。
- **未保存インジケータ**: 未保存の編集がある間、ファイル名の末尾に `*` を表示（トップバー・ステータスバー）。
  保存ボタンは isDirty のときだけ活性表示にする案。
- **ステータスバー**: 開いているファイル / 統計 / 同期状態。

## 各エリアの詳細

### A. トップバー（検索）

```
┌──────────────────────────────────────────────────────────────────────┐
│  JPDBMLEditor        [🔍 user                              ]  [×]      │
└──────────────────────────────────────────────────────────────────────┘
```

- 検索フィールドは常時表示。入力するとインクリメンタルに ER 図を絞り込む。
- **検索対象**: テーブル名 + カラム名。
- カラム名がヒットした場合、そのカラムを含む**テーブル全体**を表示し、該当カラムを**ハイライト**（[D. テーブルノード](#d-テーブルノード)参照）。
- `[×]` で検索クリア → 全体表示に戻る。
- 空文字なら全体 ER 図。

### B. 左サイドパネル

#### B-1. テーブル一覧

```
┌────────────────┐
│ テーブル一覧  ⟨ │  ← ⟨ でパネル折りたたみ
│ ────────────── │
│ ▸ users     (5)│  ← (5) はカラム数
│ ▸ orders    (7)│
│ ▸ order_items(4)│
│ ▸ products  (6)│
│ ▪ users  ← 選択中は強調
└────────────────┘
```

- 全テーブルをリスト表示。カラム数を副次表示。
- **クリック**: そのテーブルにキャンバスをパン/ズームし、フォーカスモードに入る（近傍表示）。
- 検索中は、絞り込み結果に一致するテーブルのみリストも絞る（ハイライト表示）。
- 選択中テーブルは背景色で強調。

#### B-2. フォーカス設定

```
┌────────────────┐
│ フォーカス設定   │
│ ────────────── │
│ 対象: users     │
│ ホップ数: 1     │
│ ○──●───────── │  ← スライダー（0〜最大）
│ 0  1  2  3  4  │
│                │
│ [ 全体に戻る ]  │
└────────────────┘
```

- **対象**: 現在フォーカス中のテーブル名（未フォーカス時は「なし」）。
- **ホップ数スライダー**: 初期値 1。値を上げると近傍を広げる。フォーカス中のみ有効（未フォーカス時はグレーアウト）。
- **[全体に戻る]**: フォーカス解除 → 全体 ER 図へ。

### C. ER 図キャンバス

```
                                                        ┌──────────┐
  ← モード表示（右上）                                    │ 全体 ▼    │
                                                        └──────────┘
      ┌──────────┐          ┌──────────┐
      │ users     │─────────▶│ orders    │
      └──────────┘  1     N  └──────────┘

                                                        ┌─────────┐
  ← ズーム操作（右下）                                    │ + − ⊡ ⟳ │
                                                        └─────────┘
```

- React Flow の無限キャンバス。ドラッグでパン、ホイールでズーム。
- **パン（スクロール）はどこを掴んでもできる**（2026-07-14 決定）: 背景の空白だけでなく、テーブルノードのカラム行や本体を掴んでドラッグしてもパンになる。テーブル移動は「テーブル名の青いヘッダー（タイトルバー）」を掴んだときだけ（ウィンドウのタイトルバー移動と同じ発想）。「スクロールをどこを掴むか気にせずできる」ことを優先し、ノード移動はヘッダーに限定する。実装は React Flow の `dragHandle`（`.table-drag-handle`）で掴み分ける。詳細は [D. テーブルノード](#d-テーブルノード)の「ヘッダー／ドラッグ」を参照。
- **右上モード表示**: `全体` / `絞り込み: "user"` / `フォーカス: users (1ホップ)` を表示。クリックでモード切替メニュー。
- **右下ズーム操作**: `+`（ズームイン）`−`（ズームアウト）`⊡`（全体にフィット）`⟳`（自動レイアウト再実行）。
- **リレーションのエッジ**: 端に多重度（`1` / `N`）を表示。1:1 / 1:N を描き分ける。
- **背景の空白クリック**: フォーカス解除（全体に戻る）。

### D. テーブルノード

```
┌───────────────────────┐
│ users              [+] │  ← ヘッダー: テーブル名 + カラム追加ボタン
├───────────────────────┤
│ 🔑 id      int    PK   │  ← 🔑 = 主キー
│ ▓▓ email   varchar     │  ← ▓▓ = 検索ヒットのハイライト行
│    name    varchar     │
│    age     int         │
│ 🔗 role_id int    FK   │  ← 🔗 = 外部キー（リレーション元）
└───────────────────────┘
```

- **ヘッダー**: テーブル名。右に `[+]`（末尾にカラム追加）ボタン。**フォーカス中テーブルのみ**表示。右クリック追加（[E-1](#e-1-mvp-右クリックでカラム追加--その場で入力)）の補助として、位置を問わず末尾追加したいとき用。**このヘッダー（青いタイトルバー）がノード移動の掴み手（ドラッグハンドル）を兼ねる**（後述のドラッグを参照）。`[+]` ボタンはドラッグ対象外（`nodrag`）。
- **カラム行**: アイコン（🔑 PK / 🔗 FK）+ カラム名 + 型 + 制約。フォーカス中はこの行がインライン編集グリッドになる（[E. カラム編集](#e-カラム編集インライングリッド編集)）。
- **検索ハイライト**: ヒットしたカラム行を強調（背景色 or マーカー）。
- **クリック**: そのテーブルにフォーカス（近傍表示）。カラム行・本体どこをクリックしてもよい。
- **ダブルクリック**: そのカラム行を編集状態にする（フォーカス遷移込み。[E. カラム編集](#e-カラム編集インライングリッド編集)）。
- **右クリック**: カラム行上でコンテキストメニュー（カラム追加など）。
- **ドラッグ（ヘッダー＝青いタイトルバーのみ）**: 配置移動（座標は `.jpdbml.json` に保存 → フェーズ 5）。**ヘッダー以外（カラム行・本体）を掴んだドラッグはノード移動ではなくキャンバスのパンになる**（2026-07-14 決定。ウィンドウのタイトルバー移動と同じ発想で、「スクロールをどこを掴むか気にせずできる」ことを優先）。React Flow の `dragHandle`（`.table-drag-handle`）でヘッダーだけを掴み手にする。行内ドラッグハンドル（将来の行並べ替え [E-2](#e-2-将来拡張-excel-相当の表操作)）とも、掴み手がヘッダー／行左端の⋮⋮で分かれるため競合しない。

### E. カラム編集（インライングリッド編集）

編集は **Excel ライクなインライングリッド**を目指す。テーブルノードそのものが表（グリッド）として振る舞い、ノード上で直接カラムを追加・入力できる。別パネルやモーダルには逃がさず、「見えている表をその場でいじる」体験にする。

#### E-1. MVP: 右クリックでカラム追加 → その場で入力

フォーカス中テーブルのカラム行の上で**右クリック**すると、クリック位置にコンテキストメニューが出る。

```
┌───────────────────────┐
│ users              🔒 │  ← フォーカス中は編集可
├───────────────────────┤
│ 🔑 id      int    PK   │
│ ▓▓ email   varchar     │◀─右クリック
│    name    varc┌──────────────────┐
│    age     int │ ここにカラムを追加 │
│ 🔗 role_id int │ 上に追加          │
└────────────────│ 下に追加          │
                 └──────────────────┘
```

右クリックメニューの「（上/下に）カラムを追加」を選ぶと、その位置に**空の入力行**が挿入され、そのままセルにフォーカスが入って直接入力できる。

```
┌───────────────────────────────┐
│ users                         │
├───────────────────────────────┤
│ 🔑 id       int      PK        │
│ ▓▓ email    varchar            │
│ [__________][_______▼][制約 ▼] │  ← 挿入された空の入力行（編集中）
│    name     varchar            │  ← ↑ カーソルはカラム名セルに
│    age      int                │
└───────────────────────────────┘
```

- **セル構成**: `カラム名` / `型`（ドロップダウン + 自由入力）/ `制約`（PK・NOT NULL 等）。
- **セル間移動**: `Tab` で次のセル、`Shift+Tab` で前のセル（Excel 感覚）。
- **確定**: `Enter` で行を確定 → 該当テーブル定義ブロックへ**最小編集**で 1 行挿入 → 保存 → 再パース。
- **中断**: `Esc` で空行を破棄。
- **カラム名**: 必須。空 / 重複はエラー表示（セルを赤縁 + トースト）。
- MVP では「1 行ずつ追加して確定」までを対象。複数行同時編集は将来拡張。

#### E-2. 将来拡張: Excel 相当の表操作

MVP では未実装だが、UI 設計としては以下を見据えてノードを表として作り込む（後付けで大改修にならないよう、この段階で構造を意識しておく）。

```
┌───────────────────────────────┐
│ users                         │
├───────────────────────────────┤
│ ⋮⋮ 🔑 id       int      PK     │  ← ⋮⋮ = ドラッグハンドル（行並べ替え）
│ ▏▉ ▓▓ email    varchar         │  ← 選択中の行（範囲選択で複数行）
│ ▏▉    name     varchar         │  ← ↑ Shift/Cmd クリックで複数選択
│ ⋮⋮    age      int             │
└───────────────────────────────┘
```

- **行の複数選択**: クリック + `Shift`（範囲）/ `Cmd/Ctrl`（個別）で複数カラム行を選択。
- **コピー / ペースト**: 選択した複数カラムを `Cmd/Ctrl+C` でコピー、別テーブルや同テーブルに `Cmd/Ctrl+V` でペースト。DBML のカラム定義行として貼り付く。
- **行の並べ替え**: 各行左端の**ドラッグハンドル（⋮⋮）**を掴んで上下にドラッグし、カラムの順番を入れ替え。
- **セル直接編集**: 既存カラムのセルをダブルクリックで名前・型・制約を編集（MVP のカラム追加を全カラムに一般化）。
- **行削除**: 選択行を `Delete` で削除。
- いずれも「最小編集で書式保持」の原則を守る（[全体設計.md](全体設計.md) の編集方針）。並べ替え・コピペは複数行の差分をまとめて最小編集する必要があり、位置マッピングの精度が要件になる（[未決事項](#未決事項)）。

## 表示モードと状態遷移

3 つの表示モードを持ち、右上のモード表示に反映する。

```
        検索入力(空でない)
   ┌───────────────────────────┐
   │                           ▼
┌──────┐  テーブルクリック   ┌──────────┐
│ 全体  │──────────────────▶│ フォーカス │
│      │◀──────────────────│           │
└──────┘  全体に戻る/背景    └──────────┘
   ▲       クリック              │
   │                           │ 検索入力
   │  検索クリア(×/空)          ▼
   │                       ┌──────────┐
   └───────────────────────│ 絞り込み  │
                           └──────────┘
```

| モード | トリガー | 表示内容 | 抜け方 |
|--------|----------|----------|--------|
| **全体** | 初期状態 / 検索クリア / 全体に戻る | 全テーブル + 全リレーション | テーブルクリック / 検索入力 |
| **絞り込み** | 検索フィールドに入力 | ヒットするテーブルのみ（ヒットカラムはハイライト） | 検索クリア |
| **フォーカス** | テーブルクリック / 一覧クリック | 対象テーブル + N ホップ近傍 | 全体に戻る / 背景クリック |

- 絞り込み中にテーブルをクリックしたらフォーカスに移る（絞り込み結果からのフォーカスも可）。
- モードは排他。現在モードは常に右上に明示。

### 表示方式: 配置は動かさない・濃淡 + カメラズームで表現（2026-07-13 決定）

以前は「対象外テーブルを非表示にして ELK で部分再レイアウト」する方式だったが、モードが変わるたびにレイアウトが組み変わり表示が飛ぶ問題があったため、以下の方式に変更した（確定事項・選択の余地なし）。

- **レイアウトはモデルにつき1回だけ**: ファイル読み込み/再パース時に全テーブルを対象に ELK で自動レイアウトを計算し、以降はモード変更（全体/絞り込み/フォーカス、ホップ数変更）で再レイアウトしない。テーブルの座標は常に不変。
- **対象外は「非表示」ではなく「薄く」**: 全ノード・全エッジを常時描画し、モードに応じて対象外を低opacity（0.2程度）にする。
  - フォーカス: 起点=強調ボーダー、Nホップ近傍=通常表示、それ以外=薄く。エッジは両端が近傍集合内なら通常、そうでなければ薄く。
  - 絞り込み: ヒットテーブル=通常+ヒットカラムハイライト、非ヒット=薄く。エッジも両端ヒットのみ通常。
  - 全体: すべて通常表示。
  - 薄いテーブルもクリック/ダブルクリック等の操作は今まで通り有効（薄いテーブルをクリックしてフォーカス移動できる）。
  - opacityの変化はCSS transition（0.2s程度）で滑らかにする。
- **カメラ（視点）だけが自動で動く**: フォーカス開始/ホップ数変更時・検索クエリ確定時・全体モードに戻ったときに、対象ノード群へ `fitView` でスムーズにズームする（配置自体は動かない）。検索ヒット0件なら視点は動かさない。
- **絞り込みヒット0件の空状態**: 全テーブルが薄くなるだけでは分かりにくいため、従来通りキャンバス中央に「該当なし」のオーバーレイ表示を維持する。

## 主要な操作フロー

### フロー 1: ファイルを開いて全体を見る

```
起動 → [ファイルを開く] → .dbml 選択
     → パース → 自動レイアウト → 全体 ER 図表示
     → （以降）VSCode で編集・保存しても自動では反映されない
     → 見たくなったら [手動リロード] ボタンで取り込み（未保存編集があれば破棄確認）
```

> 2026-07-14 決定: ファイル監視は廃止し、外部編集の取り込みは手動リロードボタンに一本化した
> （[計画-保存UNDO計画.md](計画-保存UNDO計画.md)）。

### フロー 2: 目的のテーブルを探してフォーカス

```
検索フィールドに "order" 入力
     → 絞り込みモード（orders, order_items がヒット）
     → orders をクリック
     → フォーカスモード（orders + 1 ホップ近傍）
     → ホップ数スライダーを 2 に
     → 近傍が 2 ホップに広がる
```

### フロー 3: カラムを追加する（インライン編集）

```
フォーカス中の users ノードのカラム行で右クリック
     → 「下に追加」を選択
     → クリック位置に空の入力行が挿入され、名前セルにカーソル
     → "created_at" 入力 → Tab → 型 "timestamp" → Tab → 制約
     → Enter で確定
     → users 定義ブロックへ 1 行を最小編集でメモリ上のテキストに反映（Undo 履歴に積む、この時点ではファイル未変更）
     → 再パース → ノードに新カラムが反映（未保存インジケータ `*` が付く）
     → 保存ボタン / Cmd+S で明示保存 → ファイルに書き込み
```

> 2026-07-14 決定: 編集は即ファイル保存せず、明示保存（保存ボタン/Cmd+S）まではメモリ上のみの変更。
> Cmd/Ctrl+Z で直前の編集を Undo できる（[計画-保存UNDO計画.md](計画-保存UNDO計画.md)）。

## 実サンプルからの知見

`SampleDBML/` にローカルで置いている実データ（大規模サンプル = 42 テーブル、小規模サンプル = 12 テーブル。`.gitignore` 済みでリポジトリには含まれない）を確認して分かった、UI が耐えるべき現実の特徴。Excel から自動生成された業務 DB スキーマで、以下は本アプリの主要な想定入力とする（例はすべて架空のものに置き換えてある）。

### 特徴と UI への反映

| 実データの特徴 | 例 | UI への反映 |
|----------------|-----|-------------|
| **カラム名が日本語＋要ダブルクオート** | `"所属部署CD"` `"汎用区分CD"` | ノード幅を可変に。インライン編集のセルは日本語 IME 入力前提。表示時のクオートは省いて見せる。 |
| **1 テーブルのカラム数が多い** | マスタ系テーブルで十数〜数十本 | ノードの**折りたたみ / 高さ制限＋スクロール**が実質必須。全カラム展開は任意。 |
| **全テーブル共通の末尾カラム** | 登録日時/登録者/更新日時/更新者/バージョン番号など | 「共通カラムを畳む」トグルがあると全体像が見やすい（将来拡張候補）。 |
| **複合主キー・複合外部キー** | `Ref: M_XXX.("A","B") < M_YYY.("C","D")` | PK が複数行に付く表示。エッジは複合キーをまとめて 1 本で描く。 |
| **note に改行と独自記法** | `note: '1：有効、2：無効\n定数: enum状態区分'` | note はノードに全部出さず**ツールチップ / 展開**で見せる。`\n` を改行表示。 |
| **Enum が多い** | 大規模サンプルに 23 個 | 型ドロップダウン（[E 節](#e-カラム編集インライングリッド編集)）に**定義済み Enum も候補**として出せると良い。ER 図に Enum ノードを出すかは要検討。 |
| **リレーションが 0 件のスキーマ** | 小規模サンプルは Ref なし | **エッジ無しでも成立**する UI。フォーカス（近傍）は「自分だけ」になっても破綻しない。テーブル一覧ナビが主役になる。 |
| **パーサが無視する独自ディレクティブ** | `// @sequence name=...` コメント行 | 最小編集で**これらのコメント行を絶対に壊さない**。行削除・並べ替え時の位置マッピングで巻き込まない。 |

### 設計上の含意

- **小規模サンプルのようにリレーションが無い**ケースがあるため、「テーブル一覧」パネル（[B-1](#b-1-テーブル一覧)）は飾りでなく主要ナビ。検索とセットで探索できることが重要。
- **note の情報密度が高い**。カラム行に出しすぎると破綻するので、`note` はアイコン（💬 等）＋ホバーで見せる方針にする。
- **共通カラムの繰り返し**が多く、ER 図全体では冗長。将来的に「共通カラムを畳む」表示オプションを検討（未決事項に追加）。
